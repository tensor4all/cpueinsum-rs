# cpueinsum 0.3.0: the tcontract 0.3 allocation-free raw API and one batch policy

Date: 2026-10-18. Branch `release/0.3-chain`. Plan: tensor4all/tcontract-rs#62,
tensor4all/cpueinsum-rs#23, tcontract-rs#123.

## What moved

* **Pins.** `tcontract`, `tcontract-exec` and `tcontract-capi` are git
  dependencies at the 0.3.0 release revision `3239c86`; `strided-basic`,
  `strided-view` are `=0.6.0`. `strided-perm` is dropped: cpueinsum-blas now
  compiles `strided_basic::CopyPlan` at plan time for both input packing and
  the opposite-direction output write-back. `cpueinsum` still has no BLAS or C
  toolchain (`cargo tree -p cpueinsum` shows neither).
* **Batch policy (#123).** `cpueinsum::GroupedPlan` resolves lanes before any
  write. `Auto` keeps the historical
  `min(width_for(2*total_macs*NS_PER_FLOP*complex), budget, jobs).max(1)`
  locally, because the shared generic `Auto` fans two tiny scalar jobs onto
  two lanes and the packed balanced-lanes rule adds a restriction this route
  does not have. Every forced strategy goes through `Exec::batch_decision` on
  the original host budget and never falls back; forced `Inner`/`Split` hand
  the decided `item_threads` to each child, so both widths run. `GroupedRoute`
  gained `Inner`/`Split` to report them.
* **cpueinsum-blas.** Its grouped route is a per-job CBLAS GEMM loop, so it
  reports `vendor_batch = false` and refuses a forced `WholeBatchVendor`
  before every shortcut. `Auto` and `Sequential` keep the vendor loop; forced
  `Outer`/`Inner`/`Split` go to the native alternative that honors the shared
  decision.
* **Raw API (#23).** `EinsumSpecRef` + `EinsumPlan::compile` compile once from
  a borrowed description. `workspace_len` is the element arena for
  intermediates and backend work; `native_workspace_req` folds the native
  tcontract `WorkspaceReq` component-wise over the sequential steps and
  documents workspace preparation. The grouped serial route drives jobs by
  index and the parallel route gives each lane a contiguous job range with its
  own output chunk, so neither collects one slot per job. The batch odometer is
  a `strided_view::AxisVec` (inline through rank eight, spill above), not a
  per-call `Vec` and not an eight-axis limit.

## Post-review corrections

* Parallel grouped lane boundaries are monotone: empty jobs sort last and may
  carry a smaller offset, so a boundary is the furthest non-empty output end of
  the lane, never the next lane's first offset. Otherwise a boundary could move
  backwards and panic an earlier lane.
* A child granted item threads now runs under a forced `Inner` policy at that
  budget, so the granted width is executed; a reset to `Auto` let a 64^3 item
  fall below Auto's threshold and run serially while reporting several threads.
* A multi-lane dispatch refuses a child route that needs a packed SPMD team
  before dispatch, because that team (a pool broadcast) is unavailable from the
  worker each lane runs on.
* `EinsumPlan::execute_bounded` replays from a caller `Workspace` and element
  arena and refuses a short one before writing, instead of growing it.
* `cpueinsum_blas::BinaryPlan` resolves forced `WholeBatchVendor` before the
  vendor/native shortcut in both prepared-binary entries.
* The BLAS packing allocation test and overhead case now use an operand that is
  not BLAS-readable in either orientation, so `CopyPlan` packing really runs; the
  output pack no longer compiles an unused forward plan.

## Verification

Full local gate with `-j 4`: `cargo fmt --all`, `cargo clippy --workspace
--all-targets -- -D warnings`, `cargo test --workspace`, `cargo test --release
--workspace` — all green. Rust-owned allocation gates
(`crates/*/tests/alloc_free.rs`, one test per binary) hold zero on the warmed
serial binary/einsum/grouped steady states; a second parallel grouped test
bounds allocations by `8 + 2*lanes` for the decided lane count.

Overhead smoke (`OVERHEAD_GATE=1 RAYON_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1`)
on this host, release, single Rust and provider thread
(`crates/cpueinsum/benches/overhead_smoke.rs`,
`crates/cpueinsum-blas/benches/overhead_smoke.rs`):

```
C1  accumulate/uninit n=2           ratio 1.003 <= 1.5 ok
C1  accumulate/uninit n=4           ratio 1.016 <= 1.5 ok
C1  accumulate/uninit n=16          ratio 1.104 <= 1.5 ok
C2  packed/contiguous               ratio 1.838 <= 2.0 ok (provider threads 1)
C3  prepared binary n=2/n=4         56.6 / 67.2 ns
C4  binary/grouped n=8              90.2 / 129.3 ns
C4  binary/grouped n=16             285.6 / 317.6 ns
```

The gates are ratios measured in the same run, so a noisy runner cannot fail
them spuriously; the absolute numbers are reported only. The post-review C2
case packs an operand with no unit stride on either axis, so the plan-time
`CopyPlan` really runs; the earlier `[16, 1]` operand was directly readable
transposed and exercised no packing.

The BLAS provider is pinned in CI through `OPENBLAS_NUM_THREADS=1` (its
`openblas_get_num_threads()` reports 1) because `Exec::serial` cannot control
it, and Rust measurements run with `RAYON_NUM_THREADS=1`.
