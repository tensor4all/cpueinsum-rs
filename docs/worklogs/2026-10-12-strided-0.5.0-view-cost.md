# strided-rs 0.5.0: the per-call view wrapper cost

Date: 2026-10-12. Branch `bump/strided-0.5.0`.

## Context

`docs/worklogs/2026-10-05-initial-implementation.md` recorded that building a
`StridedView` per operand cost about 70 ns per step (two `Arc` allocations per
view; chi=2 MPS overlap: 126 ns/step with views, 55 ns/step with slices), which
is why execution goes through `execute_slices` internally.

tensor4all/strided-rs#297 removes those `Arc`s: a view's shape and strides are
now `Cow<'_, [_]>`, so `StridedView::new` borrows the caller's layout and
allocates nothing.

## Measurement

Machine: AMD Ryzen AI 9 HX 470, Linux x86-64 (Ubuntu 24.04, kernel
7.0.0-38-generic), rustc 1.99.0, release profile, pinned to one core with
`taskset -c 2`. Backend configuration is explicit 1T:
`Exec::serial_with_workspace(&ArenaProvider)`, no Rayon pool and no BLAS
provider; `Exec::budget()` is 1. Timed boundary: one `execute_into` or one
`execute_slices` on one warm prepared `BinaryPlan<f64>` for
`D[i,l] = sum_j A[i,j] B[j,l]` over 2x2 column-major operands, operands and
output preallocated outside the loop, `N = 5e5` calls, median of three rounds,
`crates/cpueinsum/examples/op_overhead.rs`.

| route | strided 0.4.8 | strided 0.5.0 |
| --- | --- | --- |
| `execute_into`, three views built per call | 92.5 ns/call | 20.2 ns/call |
| `execute_slices`, no view | 18.3 ns/call | 18.7 ns/call |
| wrapper delta (views - slices) | 74.2 ns | 1.6 ns |
| three views alone, outside the call | 74.0 ns | 5.2 ns |

The whole improvement is the construction cost, and the view entry is now
within noise of the slice entry. The slice path inside `EinsumPlan::execute_into`
stays as it is: it is what keeps intermediates free of views, and it is no
longer load-bearing for the *caller's* operands.

## Consequence

A host no longer needs an `execute_slices`-style entry point only to avoid view
construction; both routes cost the same. The per-step internal slices remain
because they avoid building a view per intermediate, which 5.2 ns per three
views still favours on small steps.
